# 태그 기능 — 이슈 분해 (수직 슬라이싱)

> 기준 문서: [`prd.md`](./prd.md) (PRD), [`spec-fixed.md`](./spec-fixed.md) (기술 명세)
>
> **수직 슬라이싱 원칙**: 각 이슈는 데이터·API·UI를 가로지르며 **그 자체로 사용자에게 보이는 가치**를 제공한다. "데이터 모델만 추가", "API helper만 작성" 같은 수평 슬라이스는 만들지 않는다. 단, 슬라이스가 다음 슬라이스를 위한 토대 역할을 겸할 수 있다.
>
> **PRD 사용자 스토리 ↔ 이슈 매핑**
>
> | PRD US                                | 이슈                     |
> | ------------------------------------- | ------------------------ |
> | US-3 (태그 확인) — 기존 태그 표시     | TAG-1                    |
> | US-1 (태그 추가) + US-4 (저장) — 추가 | TAG-2                    |
> | US-2 (태그 삭제) + US-4 (저장) — 삭제 | TAG-3                    |
> | US-3 — 새로 추가한 태그 재표시        | TAG-2에 의해 자연히 충족 |

## TAG-1 — 노트 상세 화면에서 노트의 태그를 본다

### 설명

노트 도메인 모델에 `tags: string[]` 필드를 추가하고, `db.json` 시드의 기존 노트에 `tags: []`를 백필한다. 시연 가능하도록 시드 노트 중 1~2개에는 데모 태그(예: `["react", "demo"]`)를 미리 넣는다. `NoteEditor`에 태그 표시 영역(`TagField`의 표시 부분)을 마운트해, 선택한 노트의 태그를 chip 형태로 보여준다.

**이번 슬라이스의 가치**: 사용자가 노트 상세 화면을 열면 그 노트의 분류 태그를 한눈에 본다 (PRD US-3 부분). 동시에 다음 슬라이스(추가/삭제)가 얹힐 데이터·UI 토대가 정합성 있게 마련된다.

**스코프 안**: 표시만 — 입력/삭제 UI는 없음.
**스코프 밖**: 입력 박스, × 버튼, 저장 흐름 변경.

### 완료조건 (Acceptance Criteria)

#### AC-1.1 — 모든 노트가 `tags` 필드를 가진다

- **Given** `db.json`에 기존 노트들이 시드로 존재한다
- **When** `npm run server`로 `GET /notes`를 호출한다
- **Then** 모든 노트 도큐먼트가 `tags` 필드(`string[]`)를 가진다. 빈 배열 허용.

#### AC-1.2 — `Note` 타입이 `tags`를 필수로 요구한다

- **Given** TypeScript strict 모드가 활성화되어 있다
- **When** `npm run build`를 실행한다
- **Then** `Note` 인터페이스가 `tags: string[]`을 포함하며, 타입 에러 없이 빌드가 성공한다

#### AC-1.3 — 노트 상세 화면에서 기존 태그가 chip으로 표시된다

- **Given** 사용자가 `tags: ["react", "demo"]`를 가진 시드 노트를 선택한다
- **When** `NoteEditor`가 렌더된다
- **Then** "react"와 "demo" 두 개의 chip이 제목 input과 본문 textarea **사이**에 표시된다 (시각 위계: 제목 → 메타 → 본문)

#### AC-1.4 — 태그가 없는 노트는 빈 태그 영역만 보인다

- **Given** 사용자가 `tags: []`인 노트를 선택한다
- **When** `NoteEditor`가 렌더된다
- **Then** 태그 영역이 마운트되지만 chip은 표시되지 않는다 (placeholder 문구는 없음, 빈 공간 OK)

#### AC-1.5 — 노트 전환 시 태그 표시가 동기화된다

- **Given** 사용자가 노트 A(`tags: ["react"]`)를 보고 있다
- **When** 사이드바에서 노트 B(`tags: ["typescript", "study"]`)를 선택한다
- **Then** chip 표시가 즉시 `["typescript", "study"]`로 갱신된다 (이전 노트의 태그가 잔존하지 않는다)

## TAG-2 — 노트에 새 태그를 입력하고 저장하면 보존된다

### 설명

`NoteEditor`의 태그 영역에 텍스트 입력(input)을 추가한다. 사용자가 텍스트 입력 후 Enter를 누르면 chip이 추가된다. 입력 위생(trim, 대소문자 무시 중복 차단, 빈 입력 silent 무시, 다단어 허용, 케이스 원본 보존)을 반영한다. 저장 버튼 클릭 시 제목·본문과 함께 일괄로 서버에 전송된다 (별도 즉시 PATCH 없음). 새 노트 생성 모드와 기존 노트 편집 모드 양쪽에서 동작한다.

**이번 슬라이스의 가치**: 사용자가 자신의 분류 신호를 노트에 직접 붙일 수 있게 된다 (PRD US-1 + US-4 추가).

**스코프 안**: 입력 + 추가 + 저장 통합 + 입력 위생.
**스코프 밖**: 칩의 × 버튼/삭제 동작 (TAG-3), 태그 기반 검색·필터 (PRD Out of Scope), 자동완성.

### 완료조건 (Acceptance Criteria)

#### AC-2.1 — 입력 후 Enter로 태그가 chip으로 추가된다 (빈 상태에서 첫 추가)

- **Given** 사용자가 `tags: []`인 노트를 편집하고 있고, 태그 입력 영역에 포커스가 있다
- **When** "react"를 입력하고 Enter를 누른다
- **Then** "react" chip 1개가 표시되고, input은 비워진다 (다음 입력을 위해)

#### AC-2.2 — 기존 태그가 1개 있을 때 새 태그가 누적 추가된다

- **Given** 사용자가 `tags: ["react"]`인 노트를 편집하고 있고, 태그 입력 영역에 포커스가 있다
- **When** "typescript"를 입력하고 Enter를 누른다
- **Then** 두 개의 chip "react", "typescript"가 입력 순서대로 표시되고 (기존 chip은 사라지거나 위치가 바뀌지 않는다), input은 비워진다

#### AC-2.3 — 저장 후 새로고침 시 태그가 보존된다

- **Given** 사용자가 노트에 "react"를 추가한 상태다
- **When** "저장" 버튼을 클릭하고 페이지를 새로고침한 뒤 같은 노트를 다시 연다
- **Then** "react" chip이 다시 표시된다

#### AC-2.4 — 빈/공백 입력은 silent 무시된다

- **Given** 사용자가 태그 입력 영역에 포커스가 있다
- **When** ""(빈 문자열) 또는 " "(공백만) 입력 후 Enter를 누른다
- **Then** chip이 추가되지 않고, input은 비워진다 (alert/toast 없음)

#### AC-2.5 — 대소문자 무시 중복은 차단된다

- **Given** 노트에 이미 "JavaScript" 태그가 있다
- **When** "javascript"를 입력하고 Enter를 누른다
- **Then** chip이 추가되지 않고 (총 1개 유지), input만 비워진다 (silent)

#### AC-2.6 — 양끝 공백은 trim 후 저장된다

- **Given** 사용자가 빈 태그를 가진 노트를 편집한다
- **When** " react "를 입력하고 Enter → "저장" → 새로고침
- **Then** 저장된 태그명은 정확히 "react" (앞뒤 공백 없음)

#### AC-2.7 — 중간 공백은 보존된다 (다단어 태그 허용)

- **Given** 사용자가 태그 입력 영역에 포커스가 있다
- **When** "front end"를 입력하고 Enter를 누른다
- **Then** 단일 chip "front end"가 그대로 표시된다 (두 개로 쪼개지지 않는다)

#### AC-2.8 — 케이스는 입력 원본 그대로 저장된다

- **Given** 사용자가 빈 태그를 가진 노트를 편집한다
- **When** "JavaScript"를 입력하고 Enter → "저장" → 새로고침
- **Then** 저장된 태그는 정확히 "JavaScript" (lowercase 변환 없음)

#### AC-2.9 — 새 노트 생성 시에도 태그를 함께 저장할 수 있다

- **Given** 사용자가 "새 노트" 모드에 있다
- **When** 제목·본문과 함께 "react" 태그를 입력 후 "저장"한다
- **Then** 신규 생성된 노트가 `tags: ["react"]`를 가지고 사이드바/상세 양쪽에서 정상 표시된다

#### AC-2.10 — 저장 전 다른 노트로 이탈하면 태그 변경은 폐기된다

- **Given** 사용자가 노트 A에 "react"를 추가했지만 저장 버튼을 누르지 않았다
- **When** 사이드바에서 노트 B로 이동했다가 다시 노트 A로 돌아온다
- **Then** "react"는 보이지 않는다 (변경 폐기 — 제목/본문과 동일 정책)

#### AC-2.11 — 콤마/스페이스/탭은 확정 트리거가 아니다

- **Given** 사용자가 태그 입력 영역에 포커스가 있다
- **When** "react,vue" 또는 "react vue"를 입력한다 (Enter 없음)
- **Then** chip은 추가되지 않고, input에 입력 문자열이 그대로 남는다 (다단어 태그 가능성을 위해 Enter만 트리거)

## TAG-3 — 노트의 태그를 개별 삭제하고 저장하면 사라진다

### 설명

표시된 각 chip에 hover 시 `×` 버튼이 노출되고, 클릭하면 해당 태그만 즉시 로컬 상태에서 제거된다. 별도 확인 모달은 없다. 다른 변경(제목·본문·다른 태그 추가)과 함께 "저장" 버튼 클릭 시 일괄로 서버에 반영된다.

**이번 슬라이스의 가치**: 사용자가 잘못 붙였거나 더는 관련 없는 태그를 빼내고 정리할 수 있다 (PRD US-2 + US-4 삭제).

**스코프 안**: × 버튼 노출/삭제/저장.
**스코프 밖**: 전역 태그 삭제(rename/merge — PRD Out of Scope), 확인 모달, 실행 취소(undo).

### 완료조건 (Acceptance Criteria)

#### AC-3.1 — chip hover 시 × 버튼이 노출된다

- **Given** 노트에 "react", "demo" 두 태그가 있다
- **When** 사용자가 "react" chip 위에 마우스를 올린다
- **Then** "react" chip 우측에 × 버튼이 노출된다 ("demo" chip의 × 는 노출되지 않는다 — 개별 노출)

#### AC-3.2 — × 클릭 시 해당 chip만 제거된다

- **Given** 노트에 "react", "demo" 두 태그가 있다
- **When** 사용자가 "react" chip의 × 버튼을 클릭한다
- **Then** "react" chip이 즉시 사라지고, "demo"는 그대로 표시된다 (확인 모달 없음)

#### AC-3.3 — 삭제는 즉시 서버 반영되지 않는다 (bulk 저장 정책)

- **Given** 노트에 "react" 태그가 있다
- **When** 사용자가 × 버튼을 클릭하고 **저장 없이** 페이지를 새로고침한다
- **Then** "react" 태그가 그대로 다시 표시된다 (서버 미반영, 로컬 변경만 폐기됨)

#### AC-3.4 — 저장 후 새로고침 시 삭제가 보존된다

- **Given** 사용자가 "react" 태그를 × 버튼으로 삭제한 상태다
- **When** "저장" 버튼을 클릭한 뒤 페이지를 새로고침한다
- **Then** 해당 노트에 "react" 태그가 더는 표시되지 않는다

#### AC-3.5 — 모든 태그 삭제 후 빈 상태가 자연스럽다

- **Given** 노트에 태그가 1개("react")만 있다
- **When** × 버튼으로 삭제 → "저장" → 새로고침
- **Then** 태그 영역이 마운트되되 chip은 없음 (TAG-1 AC-1.4와 동일한 빈 상태)

#### AC-3.6 — 같은 세션 내 추가/삭제 혼합 동작

- **Given** 노트에 "react"가 있다
- **When** "vue"를 추가하고 → "react"를 × 로 삭제하고 → "저장" → 새로고침
- **Then** 최종 태그는 정확히 `["vue"]` (순서·내용 모두)

#### AC-3.7 — 삭제 후 같은 이름 재추가가 가능하다

- **Given** 노트에 "react"가 있다
- **When** "react"를 × 로 삭제 → 즉시 input에 "react" 입력 후 Enter
- **Then** "react" chip이 다시 추가된다 (TAG-2 중복 판정은 "현재 표시 중인 chip" 기준이므로 삭제 직후 재추가는 정상 동작)

## Not Issued (의도적으로 이슈로 만들지 않은 항목)

수직 슬라이싱 원칙상 **사용자 가치가 없는 순수 인프라/기술 부채는 별도 이슈로 분리하지 않는다**. 다음 항목은 의도적으로 제외:

| 항목                                                               | 이유 / 처리 방향                                                                                                                         |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **`updateNoteTags(id, tags)` API helper** (PRD ADR-003 future-use) | 현재 사용처 없음 — 사용자 가치 0. "즉시 저장 모드 토글" 같은 사용처가 생기는 별도 이슈에서 함께 도입. 이번 3개 이슈에는 포함하지 않는다. |
| **태그 기반 검색/필터**                                            | PRD §4.1 Out of Scope. 별도 PRD/이슈로.                                                                                                  |
| **`NoteList` 사이드바에서 태그 미리보기**                          | PRD §4.1 Out of Scope. 시각 노이즈 검토 후 별도 결정.                                                                                    |
| **태그 자동완성**                                                  | PRD §4.1 Out of Scope. ADR-001 데이터 구조에 의존.                                                                                       |
| **태그 색상/메타데이터**                                           | PRD §4.2 Out of Scope. 1급 시민화 마이그레이션 후.                                                                                       |
| **태그 rename / merge**                                            | PRD §4.2 Out of Scope. 1급 시민화 후.                                                                                                    |
| **사용자 알림 toast/modal** (중복 시 안내 등)                      | PRD §4.4 Out of Scope. `alert()` 금지 룰. UX 불만 누적 시 별도 PRD.                                                                      |
| **모바일/터치 UI 최적화** (× 버튼 항상 노출 변형 등)               | PRD §4.4 Out of Scope. 별도 반응형 작업.                                                                                                 |
| **컴포넌트 의존성 다이어그램 재생성**                              | 구현 완료 후 `mermaid-diagram` skill로 1회 재생성 (각 이슈가 아닌 마무리 작업).                                                          |

## 의존성 / 진행 순서

```
TAG-1 ──┬──> TAG-2
        └──> TAG-3
```

- TAG-1이 데이터 모델과 표시 토대를 제공하므로 가장 먼저.
- TAG-2와 TAG-3는 TAG-1 이후라면 **서로 독립적으로 진행 가능**. 권장 순서는 TAG-2 → TAG-3 (추가가 먼저 동작해야 삭제 시연이 자연스러움).
- 각 이슈는 완료 후 **다음 이슈 시작 전에 머지** 권장 (작은 단위 머지 → 회귀 추적 쉬움).
